# 分析框架与洞察质量标准

本文件回答"什么叫一份好结论"，供生成分析结论时对照。

## 一、发现 ≠ 洞察

- **发现（Finding）**：陈述数据里发生了什么。例："某单品销量从 97292 降到 81332。"
- **洞察（Insight）**：解释为什么重要、该怎么办。例："该单品销量 ↓16.8%，作为榜单头部，其动能减弱会拖累整体大盘，需优先排查是否被同价位新品分流，并准备促销预案。"

把发现升级为洞察，要三个要素齐备：

1. **模式**：数据呈现出什么（趋势、对比、异常）
2. **解释**：最可能的原因是什么
3. **含义**：对决策或行动意味着什么

三者缺一，就只是复述数据。

## 二、洞察的四个层次

| 类型 | 回答的问题 | 用途 |
|---|---|---|
| 描述型 | 发生了什么、多大？ | 建立基线 |
| 诊断型 | 为什么发生？ | 找根因 |
| 预测型 | 接下来会怎样？ | 预判风险 |
| 处方型 | 应该怎么做？ | 给建议 |

不要停在描述型——那是汇报，不是分析。数据条件允许时，至少做到诊断 + 处方。

## 三、三次追问法

每个重要发现之后，连问三次"那又怎样"，第三次的答案才是值得写进结论的洞察。

- 发现：某单品月销量 81332
- 追问 1：比首月少了 16.8%
- 追问 2：它原本是榜单头部，下滑会拉低整体大盘
- 追问 3：头部动能减弱，需优先排查是否被同价位新品分流，并准备促销预案

## 四、量化门槛

没有数字支撑的判断只能算观察，不能算洞察。可用的量化方式：

- **绝对量**：增减多少件 / 多少元
- **相对量**：增减百分比、占比
- **增速**：同比、环比、复合增速
- **结构**：Top-N 集中度、价格带分布

## 五、优先级：影响 × 置信度

| | 高置信度 | 低置信度 |
|---|---|---|
| **高影响** | 优先 1：直接写进结论 | 优先 2：写进去并标注需验证 |
| **低影响** | 优先 3：可作背景一句带过 | 优先 4：不写 |

优先 4 的内容要直接砍掉，写进去只会稀释重点。

在影响 × 置信度之外，再叠加两个筛子：

- **紧迫性**：一周内要决策的，即使置信度中等也要提前说
- **可行动性**：能直接采取动作的排前面；只能用来校准判断的次之；纯背景的不写

参考评分（每项 1-3 分，总分 5-15）：影响规模、影响人数/占比、紧迫度、置信度、可行动性。12-15 分优先呈现，8-11 分作支撑，5-7 分舍弃。量级阈值按业务实际调整。

## 六、多条发现的综合

发现超过 3 条时必须做综合，三选一：

- **主题归并**：按主题分组（如增长来源 / 下滑风险 / 结构变化），从影响最大的主题起笔
- **影响排序**：按影响分降序呈现，并说明砍掉了什么、为什么
- **一句话主线**：找一条能覆盖 80% 信息的贯穿线，作为结论段

## 七、显式说明取舍

"这几条合计贡献了 85% 的增量，其余为小幅波动，未展开"——这是论证，不是借口。

砍掉的内容要说出来，这体现严谨，而不是筛选偏差。
